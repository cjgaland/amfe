## 1. Descripción
PWA estática (sin build, sin dependencias, sin CDN) para hacer, **paso a paso y de forma didáctica**, el **Análisis Modal de Fallos y Efectos (AMFE)** de cualquier proceso sanitario: proceso y subprocesos, equipo y sesiones, fallos con efecto, causa y controles actuales, puntuación G·O·D e IPR, priorización, acciones de mejora y reevaluación. Nace del curso «Elaboración de Mapas de Riesgo en Procesos Sanitarios» (material en `/Users/Trabajo/Desktop/Calidad&Seguridad/Ecosistema Calidad/Mapa de Riesgos/Curso Mapa de Riesgo/`). Herramienta docente y de apoyo; no sustituye el criterio profesional.

Es una **herramienta** del ecosistema (funciona sola). La superaplicación **Mapa de Riesgos** y **Auditorías** podrán «Traer de AMFE» leyendo `localStorage["amfe-intercambio"]` (formato `amfe-fallos` v1, ver «Intercambio» más abajo). Hermana de Auditorías, Indicadores, Tamaño Muestral, Flujograma, DAFO · CAME, Mapa de Riesgos y Rondas de Seguridad (enlazadas desde la portada y «Acerca de»; `L.URL_AUD`, `L.URL_IND`, `L.URL_TM`, `L.URL_FLUJO`, `L.URL_DAFO` desde v2026.06, `L.URL_MAPA` = https://cjgaland.github.io/mapa-riesgos/ desde v2026.07, `L.URL_RONDAS` = https://cjgaland.github.io/rondas-seguridad/ desde v2026.08; Rondas lee `amfe-intercambio` para convertir los fallos prioritarios en preguntas de la ronda): mismos tokens CSS, modo claro/oscuro, modales, SW network-first con aviso «Actualizar», vista imprimible y PDF en iOS.

### Datos
- `localStorage["amfe-datos"]` = `{ app: "amfe", v, ultimaCopia, amfes: [] }`. Guardado con 250 ms de retardo y al salir (`pagehide`).
- Al cargar e importar se pasa SIEMPRE por `sanearDatos`. **Al añadir un campo nuevo**: añadirlo a la fábrica (`nuevoX`) y a `ESQ` en logic.js (si no, el saneado lo borra al recargar). Subir `VERSION_DATOS` solo si cambia el significado de algo ya guardado.
- AMFE: `{ id, titulo, proceso, unidad, objetivo, inicio, fin, incluye, excluye, responsable, fecha, subprocesos: [{ id, nombre, descripcion, inicio, fin, roles, color: "0"–"7" }], equipo: [{ id, perfil, cargo, rol, justificacion, nombre }], sesiones: [{ id, fecha (AAAA-MM-DD), actividad, duracion, asistentes: [idMiembro], resultados }], fallos: [{ id, num, subprocesoId, fallo, efecto, causa, controles, g, o, d, critico, motivoCritico, manual: ""|"si"|"no", motivo, acciones: [{ id, que, porque, donde, plazo, fin, quien, como, tipo: correccion|correctora|preventiva, clase: ""|procedimiento|formacion|tecnologia|organizativa, actuaSobre: [o|d|g], indicador: { nombre, formula, estandar, fuente }, comprobacion: { especifica, factible, medible, sostenible, aceptable: bool }, estado: pendiente|curso|hecha|verificada, nota }], residual: { g, o, d, fecha, nota }, votos: [{ miembroId, g, o, d }], ishikawa: [{ id, cat, texto, porques: [3], elegida }] }], ideas: [{ id, subprocesoId, texto, bloqueId, falloId }], bloques: [{ id, nombre, comentario }], tgn: { modo: "321"|"1a10", votos: [{ miembroId, bloqueId, puntos }] }, edicion: "00", anteriorId, escalas: { g, o, d: [5 textos] }, prioridad: { modo: top|umbral, n: "15", umbral: "200" }, introduccion, conclusiones, control: { elaborado, revisado, aprobado: [{ nombre, cargo }], historial: [{ edicion, fecha, cambio }] }, proxRevision, notas, creado, modificado }`.
- G, O y D se guardan como texto (lo escrito); el IPR, el puesto y la prioridad se calculan siempre. `num` es el número fijo del fallo (matriz, flujograma); el saneado renumera repetidos.
- Regla de esquema `"ent"` = entero ≥ 0; `{ lista, keepEmpty: 5 }` = lista de longitud fija (escalas).
- Enlaces en la UI: campos del AMFE con `data-k`; subprocesos `data-s` + `data-f`; equipo `data-m` + `data-f`; sesiones `data-x` + `data-f`; fallos `data-fa` + `data-f`; asistentes `data-asis` + `data-v`; acciones `data-ac` + `data-f` (ruta: `indicador.nombre`…), `data-acpick`, `data-acmulti`, `data-acchk`; residual `data-fr` + `data-f`; control `data-cp` + `data-i` + `data-f` e historial `data-ch` + `data-f`; ideas `data-idea` + `data-f`; bloques `data-bq` + `data-f`; votos del grupo nominal `data-v321` + `data-p` o `data-v10` + `data-b`; votos de G·O·D `data-vf` + `data-vm` + `data-f`. Modo reunión = clase `modo-reunion` en `body` (`ponerReunion`; Esc para salir). Ishikawa: causas `data-ik` + `data-f` (`texto` o `porques.0…2`); ejercicio de puntuar `data-pe` + `data-f`. **Ojo**: los clics con atributos propios (`data-acpick`…) se atienden ANTES de la línea `if (!(b = t.closest("[data-act]"))) return;`. Al escribir se refrescan zonas (`refrescar(idFallo)`: `[data-zona]`, `[data-zav]` avisos de cada fallo, `[data-zipr]`, `[data-zesc]`) sin perder el foco; los cambios de estructura (y los `<select>`) repintan conservando el scroll (`repintar`).
- Borradores: un AMFE nuevo vive en `borradores` hasta que se escribe algo (`esVacio`).
- Ejemplos: viven en memoria (`ejemplos()`, pasados por `sanearAmfe`; id `ej-amfe-urg`); la ruta decide `modoEjemplo`; `guardar()` solo escribe `datosUsuario`. «Copiar a mis datos» copia el AMFE con id nuevo. Nunca se importa un id `ej-`.
- **Intercambio** (Diseño, 5.3): en cada guardado se escribe `localStorage["amfe-intercambio"]` = `L.paqueteIntercambio(datosUsuario.amfes, APP_VERSION, fecha)` = `{ formato: "amfe-fallos", version: 1, app, appVersion, generado, amfes: [{ id, titulo, proceso, unidad, fecha, edicion, escalas: "curso"|{g,o,d}, criterio: { modo, n, umbral }, subprocesos: [{ id, orden, nombre, inicio, fin, roles }], fallos: [{ id, num, subprocesoId, subproceso, fallo, efecto, causa, controles, g, o, d, ipr, puesto (números o null), prioritario, motivoPrioridad: top|umbral|critico|manual|null, motivo, critico, grave, zona, acciones: [], residual: null }] }] }`. Solo datos del usuario, nunca los ejemplos. **Añadir campos no sube la versión; quitar o cambiar el significado de uno sí.** Las otras apps validan con la misma lógica que `leerIntercambio`.
